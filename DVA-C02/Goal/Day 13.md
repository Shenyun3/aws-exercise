### 5 CLI / SDK 题专项归类（20 分钟，今天的核心）

把所有标了 `C` 的题挑出来，归到下面四类，并确认每类的标准答案模式：

- [ ] **分页（Pagination）**
  - 特征：返回结果不完整、只拿到一部分数据
  - 标准答案：**检查响应里的 `NextToken` / `Marker` / `LastEvaluatedKey`，用它发起下一次请求**
  - SDK 里通常有 **paginator**（如 boto3 的 `get_paginator`）自动处理
  - DynamoDB 特有：`LastEvaluatedKey` → `ExclusiveStartKey`

- [ ] **重试与退避（Retry / Backoff）**
  - 特征：`ThrottlingException`、`ProvisionedThroughputExceededException`、`429`、`503`
  - 标准答案：**指数退避 + 抖动（exponential backoff with jitter）**
  - 记住：**SDK 默认已经内置重试**，题目常问"还需要额外做什么"→ 调整 `max_attempts`、`retry_mode`（`legacy` / `standard` / `adaptive`）
  - **抖动（jitter）存在的意义**：防止所有客户端同时重试造成二次冲击

- [ ] **错误码含义**
  - **4xx = 客户端错误**（你的请求有问题，重试同样的请求也没用）
    - `400 ValidationException` —— 参数不对
    - **`403 AccessDenied`** —— 权限问题 → 查 IAM policy / resource policy / KMS key policy
    - `404 ResourceNotFound`
    - **`429 TooManyRequests` / ThrottlingException** —— 限流 → **这个要退避重试**
  - **5xx = 服务端错误**（AWS 侧的问题）→ **应该重试**
    - `500 InternalError`、`503 ServiceUnavailable`
  - **记住这条判据：4xx 里只有 429 值得重试，其他 4xx 重试无意义；5xx 一律重试。**

- [ ] **凭证与配置**
  - `aws configure` 的 profile 机制、`--profile` 参数
  - `--query`（JMESPath 过滤输出）、`--output`（json / text / table）
  - 环境变量 `AWS_PROFILE` / `AWS_REGION` / `AWS_ACCESS_KEY_ID`
  - **credential provider chain 的顺序**——明天 Day 14 专项处理
