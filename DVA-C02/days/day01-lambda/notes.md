## 1. Execution Context（执行上下文）重用机制

### 1.1 生命周期：冷启动 vs 热调用

- **冷启动（Cold Start）**：
  1. 下载函数代码或镜像。
  2. 创建执行容器并启动运行时（Runtime）。
  3. 执行 **Handler 外部** 的初始化代码（全局导入、静态变量、数据库/SDK 客户端初始化）。
  4. 执行 Handler 函数本身。
- **热调用（Warm Invocation）**：
  - Lambda 直接复用已经初始化的执行环境。
  - **跳过 Handler 外部代码的初始化**，直接进入 Handler 接收事件并处理。
  - 处于空闲状态的执行环境会在数分钟到数十分钟无请求后被 AWS 自动回收。

### 1.2 开发者黄金法则与反模式

- **推荐实践**：
  - **数据库连接池 / HTTP Client / AWS SDK Client 必须定义在 Handler 外部**。这样在热调用时能复用 TCP/TLS 握手和连接池，大幅降低延迟并防止打满关系型数据库的连接池上限。
  - 大体积只读数据（如配置字典、机器学习静态模型）在外部单例加载到内存。
- **禁止的反模式**：
  - 在 Handler 外部存储**带有具体请求上下文或用户身份的有状态数据**（例如全局变量存储上一个调用的用户信息）。因为同一个执行环境可能接连服务不同的并发请求，会导致状态污染或数据泄露。

### 1.3 临时存储 `/tmp`

- **容量范围**：可配置 **512 MB – 10,240 MB (10 GB)**，默认 512 MB。
- **复用特性**：
  - 只要执行环境存活，写入 `/tmp` 的文件在后续热调用中**依然存在且可读写**。
  - 可作为轻量级本地磁盘缓存（如缓存下载的压缩包、临时生成的 PDF/图片）。
  - **不可作为持久化存储**：环境销毁时数据永久丢失；新并发实例启动时看不到其他实例的 `/tmp`。

## 2. 内存、CPU 与性能调优

### 2.1 内存与 CPU 绑定关系

- **内存范围**：**128 MB – 10,240 MB**，以 1 MB 递增。
- **CPU 机制**：Lambda **没有独立的 CPU 规格配置**。CPU 算力与分配的内存成严格的线性正比关系。
  - 当配置 **1,769 MB** 内存时，Lambda 提供等价于 **1 个完整 vCPU** 的算力。
  - 超过 1,769 MB 时分配多个 vCPU（最高配置 10,240 MB 时可获得最多 6 个 vCPU），代码若使用多线程/Worker 可并行加速。

### 2.2 成本与性能的反直觉调优

- **计费公式**：
  $$\text{费用} = \text{配置内存 (GB)} \times \text{执行耗时 (秒)} \times \text{单价}$$

- **反直觉考点**：
  - 对于 **CPU 密集型** 任务（如图片转码、加解密、复杂数据解析），**增加内存配置可能让总费用反而更低**。
  - 原因：内存翻倍带动 CPU 算力翻倍，执行时间可能缩短超过一半，总的 $\text{内存} \times \text{时间}$ 乘积下降。
- **调优工具**：
  - **AWS Lambda Power Tuning**：基于 Step Functions 的开源调优状态机，通过运行不同内存配置的基准测试，自动绘制出“成本最优”或“速度最优”的决策帕累托前沿图。

## 3. 并发控制：Reserved vs Provisioned

| 对比维度         | Reserved Concurrency（预留并发）                                                                             | Provisioned Concurrency（预置并发）                                         |
| :--------------- | :----------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------- |
| **核心解决问题** | **配额隔离 / 保护下游数据库 / 流量熔断**                                                                     | **消除冷启动延迟（低延迟保证）**                                            |
| **行为模式**     | 为函数锁定最大并发实例上限。即使账户总并发充足，超过该上限的请求直接抛出 `429 Too Many Requests` (Throttled) | 提前初始化指定数量的执行环境（完成 Handler 外部代码执行），随时待命处理请求 |
| **计费**         | 免费（仅设置额度上限）                                                                                       | 额外付费（按预置的容量时长 + 运行时间计费）                                 |
| **特殊考点**     | **设为 0** 可以充当**紧急断路器/熔断开关**，立即阻断该函数的所有调用                                         | 仅适用于**已发布的具体版本或 Alias**，不能直接配置在 `$LATEST` 上           |
| **弹性扩展**     | 请求在预留限制内按需冷启动扩容                                                                               | 超过预置并发的突发请求，会回退到标准冷启动实例来处理                        |

## 4. Destinations（目标）vs DLQ（死信队列）

> 极高频对比考点，务必牢记以下决策矩阵：

| 评估维度                  | Dead Letter Queue (DLQ)                                   | Lambda Destinations                                                                   |
| :------------------------ | :-------------------------------------------------------- | :------------------------------------------------------------------------------------ |
| **支持的调用类型**        | 仅异步调用（Asynchronous Invocation）                     | 异步调用 + 部分流式映射（Event Source Mapping，如 Kinesis/DynamoDB Streams 失败目标） |
| **支持的触发状态**        | **仅处理失败（OnFailure）**                               | **支持成功（OnSuccess）与失败（OnFailure）双分支**                                    |
| **支持的目标服务**        | 仅支持 **SQS** 与 **SNS**                                 | 支持 **SQS、SNS、Lambda、EventBridge**                                                |
| **传递的 Payload 丰富度** | 仅原样转发原始请求 Payload（不带错误原因、堆栈或请求 ID） | 包含丰富结构化上下文：请求详情、响应结果、异常类型、调用堆栈、Request ID、时间戳      |
| **AWS 官方推荐倾向**      | 早期遗留功能，基本被 Destinations 取代                    | **官方强烈推荐的首选方案**（解耦编排、可构建更灵活的无服务器工作流）                  |

## 5. Lambda 访问 VPC 内资源 (Skill 1.2.1)

### 5.1 Hyperplane ENI 架构

- 旧机制（2019 年前）：每个 Lambda 容器启动时附着全新 ENI，导致冷启动长达 10~30 秒，且极易耗尽子网私有 IP。
- 现行机制：采用 **Hyperplane ENI**。Lambda 服务在目标 VPC 和子网中预先建立共享弹性网络接口，不同并发实例通过网络通道复用该接口，冷启动时间大幅缩减至亚秒级。

### 5.2 核心出题陷阱：公网访问中断

- **陷阱场景**：Lambda 配置 VPC（例如关联了公共子网 Public Subnet），期望既访问 VPC 内的 RDS，又直接访问第三方公网 API。
- **现象**：调用公网 API 超时失败！
- **原理剖析**：
  - Lambda 挂载的 ENI **不具备公网 IP（Public IP）**。
  - 即使位于绑定了 Internet Gateway (IGW) 的公共子网，由于缺乏 Public IP，IGW 无法为其完成 NAT 地址转换。
- **标准解法（考试必选答案）**：
  1. 将 Lambda 配置在 **私有子网（Private Subnet）** 中。
  2. 在 **公共子网（Public Subnet）** 部署 **NAT Gateway**（并绑定 Elastic IP）。
  3. 私有子网路由表配置默认路由 `0.0.0.0/0` 指向该 NAT Gateway。
  4. 若仅访问 AWS 托管服务（如 S3、DynamoDB），优先配置 **VPC Endpoints (Gateway / Interface Endpoint)**，无需经由 NAT Gateway。

## 6. 版本（Version）与别名（Alias）

### 6.1 基本概念

- **`$LATEST`**：
  - 代码与配置的当前工作草稿，随时可编辑。
  - 不能直接用于生产环境绑定，也不支持 Provisioned Concurrency。
- **发布版本（Published Version）**：
  - 通过 `PublishVersion` 生成单调递增的数字版本（如 `1`、`2`、`3`）。
  - **完全不可变（Immutable）**：代码、环境变量、运行时参数均冻结，不能更改。
- **别名（Alias）**：
  - 指向某一具体版本的指针（例如 `PROD` 指向版本 `1`，`DEV` 指向 `$LATEST`）。
  - 调用端只需绑定 Alias ARN，版本迭代时调用方 ARN 保持不变。

### 6.2 加权流量切分（Routing Configuration）

- 一个 Alias 可以配置 **主要版本（Weight）** 和 **次要版本（Weight）**（如 90% 流量转至 `v1`，10% 流量转至 `v2`）。
- **应用场景**：Canary（金丝雀）灰度发布、A/B 测试。
- **与 CI/CD 联动**：在 Day 5 会重点考察的 **CodeDeploy**，就是通过修改 Lambda Alias 的权重实现 `Linear10PercentEvery1Minute` 或 `Canary10Percent5Minutes` 的平滑流量转移。

## 7. 配额、限制与扩展特性

| 项目                   | 配额 / 限制                 | 备考重点解读                                                              |
| :--------------------- | :-------------------------- | :------------------------------------------------------------------------ |
| **单次执行超时**       | 最长 **15 分钟** (900 秒)   | 超过 15 分钟的长任务需改用 ECS Fargate 或 Step Functions 拆解             |
| **内存分配**           | 128 MB – 10,240 MB          | 步长 1 MB；1,769 MB 对应 1 vCPU                                           |
| **临时存储 `/tmp`**    | 512 MB – 10,240 MB          | 默认 512 MB；支持跨调用缓存数据                                           |
| **部署包直接上传**     | **50 MB** (Zip 格式)        | 控制台或直接 CLI 上传的最大文件限制                                       |
| **部署包解压后体积**   | **250 MB** (含 Layers)      | 包含代码、依赖与所有挂载 Layer 解压后的总和上限                           |
| **容器镜像大小**       | **10 GB**                   | 针对超大依赖（如 PyTorch、TensorFlow）采用 Container Image 部署           |
| **层（Layers）上限**   | 最多 **5 个** Layer         | 解压后同样计入 250 MB 总限额；按配置顺序解压合并到 `/opt`                 |
| **扩展（Extensions）** | Internal / External         | 用于接入 APM 监控、安全审计探针（如 Datadog、AppDynamics、OpenTelemetry） |
| **环境变量加密**       | 默认静态加密，支持 KMS 助手 | 敏感配置（API 密钥、数据库凭证）由 KMS 加密；Skill 2.3.2 考点             |
